# 专业版式设计指南

专业管线是一块自由排版画布：Markdown 承载可编辑正文，语义组件处理重复结构，`:::raw` 承载独特 HTML/SVG 与用户素材。组件是快捷方式，不是可选版面的清单。

## 先定内容角色

开始排版前，只在内部确定五件事，然后直接写稿：

1. **阅读目标**：通知、活动转化、叙事、说明或品牌展示。
2. **信息层级**：主标题、章节、正文、重点、辅助信息分别是什么。
3. **已有素材**：照片、Logo、插画、图表、艺术字和可复用 SVG。已有品牌素材直接使用，不重新发明标识。
4. **画布**：背景、页面留白、正文字阶与主辅色。
5. **独特画面**：哪一处值得使用 raw；其余内容保持普通、可编辑的 HTML。

普通排版不需要研究平台机制、逐项 lint 或浏览器截图。规格和组件不合法时，鱼排会直接给出具体错误。

## 垂直节奏与容器留白

- 全文使用有限且一致的间距档位。同级组件的段前段后距离保持一致；重点行、章节头和独立卡片上下都要有明确分隔，不能只留一侧。
- 区分三种距离：组件外边距负责与上下文分隔，容器内边距负责文字到边框的呼吸空间，段落间距负责容器内部的阅读节奏。不要把三者混成同一个值，也不要无意义叠加。
- 插图与说明若属于同一视觉单元，应共享容器和统一的外边距；说明之后与下一个组件之间保留清晰间隔。
- 卡片与展开正文的末段仍需保留段后距和容器底部内边距。维护 `expand` / `swap` 时，用移动正文回归用例核对展开高度，确保底部留白不会被估算高度裁掉。
- 间距服务于层级，不是越大越好：同一层级统一，层级变化时有意识地区分，避免逐段随意设置像素值。
- 短强调词保持完整，不在「信息卡」「展开组件」这类固定词组内部断行；长句强调仍允许正常换行，不为避免断行制造横向溢出。

## 三种常用构图

这些构图来自对公开公众号实例的结构化观察，只保留可泛化的排版规律，不携带原账号、品牌角色、活动素材或本机路径。

### 活动长文

适合报名、上新、通知与多章节活动。

- 画布常用白色或浅灰，水平留白约 20px。
- 章节使用「大号编号／英文 + 主标题色带 + 可选副标题」，不要每章重新设计一套标题。
- 信息卡可用约 90% 宽度、10px 圆角和轻阴影，与正文画布形成层级。
- 日期、地点、名额等短重点使用小面积反白；长段落保持普通正文。
- 图片是独立内容层，图片中的文字不当作正文字体样式。

```markdown
:::chapter_header
01
本周活动
三个地点，三种参与方式
:::

:::info_card
@周六活动
**14:00–18:00｜一层中庭**
:::

:::highlight
**前 50 名到场可领取纪念卡**
:::
```

### 对话与快闪

适合答疑、人物发言、轻量互动与现场预告。

- 整页背景可以区别于卡片，形成「页面—对话／卡片—正文」三层。
- 卡片与对白不必等宽；用对齐、间距和短句建立节奏。
- 问题可以比回答更重、更大；不要让每句话都成为强调。
- 头像、气泡、麦克风和品牌角色属于用户素材或 raw 图层，不由正文组件伪造。

起步参数：

```json
{
  "page_bg": "#f2f2f2",
  "body_size": 15,
  "line_height": 1.8,
  "body_spacing": 1,
  "card_radius": 10,
  "card_padding": 20
}
```

对白、斜切标题、异形尾线和多层标签可直接在 raw 中组合 HTML/SVG；不需要把独特画面塞进固定卡片组件。

### 互动叙事

适合长图、滑屏、点击与连续视觉故事。

- 主视觉使用明确 `viewBox` 和宽高比，SVG／图片层按同一坐标系组织。
- 正文、链接、名单等需要选择和编辑的内容优先保留普通 HTML，不整篇位图化。
- 复杂画面可由位图素材、矢量路径与 SMIL 分层组成；不要把 SVG 数量或动画数量当成设计目标。
- 名单与链接保持轻量字阶，让主视觉承担视觉重量。

```markdown
:::credits
策划｜内容小组
设计｜视觉小组
:::
```

## 画布参数

通过 `fishpai_open({ xiumi_spec })` 保存到文档；预览、复制和导出读取同一份配置。`fishpai_render({ xiumi_spec })` 只覆盖当次。

| 分组 | 键 | 用途 |
| --- | --- | --- |
| 画布 | `page_bg` `page_width` `page_padding_x` `page_padding_y` | 页面底色、最大宽度与留白 |
| 标题 | `title_color` `title_size` `title_align` | Markdown 一级标题 |
| 正文 | `body_color` `body_size` `body_align` `body_spacing` `line_height` `muted_color` | 字阶、对齐、字距、行高与辅助色 |
| 卡片 | `card_bg` `card_radius` `card_padding` | 卡片、对白承载面与引文 |
| 色彩 | `accent` `accent2` | 章节、重点、图形和组件共享的角色色 |

正文常用起点是 15px、1.8–2 倍行高、0.5–2px 字距；这是参数起点，不是必须照抄的模板。整页主视觉可使用 `page_padding_x: 0`，普通长文通常保留约 20px 留白。

## 素材与字体

- 用户提供的照片、Logo、插画与艺术字都是排版材料，可以裁切、缩放、叠层、加色块或与 SVG 组合。
- 相同材料下的复刻可以自由重建布局，不要求逐段落入现有指令。
- 原创 SVG 适合几何主视觉、图标、分隔、路径艺术字和交互动画；已有标识应使用已有图形。
- 正文使用系统默认字体。特殊字体效果转成图片或矢量路径，不依赖网页字体，也不把位图里的字当作 CSS 字体能力。
- 图片必须有明确显示宽度；需要固定比例时同时约束容器或 SVG `viewBox`，避免加载后跳动。
- 不擅自补写用户未提供的活动时间、地点、价格、名单或品牌信息。

## 配色与深色模式

一篇文章输出一套明确的内联配色。阅读端可能进行深色转换，因此不要依赖 `prefers-color-scheme` 在编辑端生成双主题，也不要把浅色截图当作另一份设计。

深色转换由微信阅读端处理。维护组件时运行自动回归；最终候选如需真实设备检查，一次完成即可，不在创作中途反复要求用户验收。

## raw 的创作边界

`raw` 用于原创设计与同等素材复刻，原样保留安全 HTML/SVG，可与其他块交替：

```markdown
:::raw
<section style="width:100%;background-color:#17213a;padding:32px 24px;box-sizing:border-box;">
  <svg viewBox="0 0 640 360" role="img" aria-label="活动主视觉" style="display:block;width:100%;height:auto;">
    <rect x="0" y="0" width="640" height="360" fill="#17213a"/>
    <path d="M80 220 C180 80 380 80 560 210" fill="none" stroke="#8aa8ff" stroke-width="28" stroke-linecap="round"/>
  </svg>
</section>
:::
```

鱼排拒绝脚本、事件处理器、iframe、外链样式、表单与危险 URL。不要把绕过校验当作排版能力；需要的效果用安全 HTML、内联样式、SVG 和用户素材实现。

## 一次完成的工作流

1. `fishpai_open`：正文与画布规格一起建立。
2. 写 Markdown、语义组件和必要的 raw。
3. 面板复制或 `fishpai_render` 导出。
4. 工具报出具体规格、组件或素材错误时，只修对应问题。

只有用户明确要求深度视觉复刻、维护渲染组件或更新仓库预览图时，才进入截图比对与浏览器排障；普通写作 Agent 不承担这部分工作。
